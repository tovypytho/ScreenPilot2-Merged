## 3. Phase 3.2 — MethodChannel Bridge

### 3.1 Kotlin side — `CaptureBridge.kt`

- MethodChannel `id.eujian.cbt.screenpilot/capture`, method `capture`.
- `CaptureProviderRegistry.get()` null → `{ok:false, error:"provider_unavailable"}`.
- `CaptureResult.Success` → PNG written to `context.cacheDir` as `capture_<yyyyMMdd_HHmmss_SSS>.png` → `{ok:true, path, width, height}`.
- `CaptureResult.Denied` → `{ok:false, error:"capture_denied"}`; `CaptureResult.Error` → `{ok:false, error:<message>}`.
- Handler on `Dispatchers.Main.immediate` scope; PNG write on `Dispatchers.IO`; reply on the platform main thread.

### 3.2 Flutter side — `main.dart`

- MethodChannel with state `_imagePath` / `_status` / `_dimensions`.
- "Capture via Bridge" button → `invokeMethod('capture')` → `Image.file(File(path))`; status and dimensions rendered below the image.

### 3.3 Wiring — `MainActivity.kt`

- `openFlutterTest()` creates + caches a FlutterEngine (`FlutterEngineCache`, id `screenpilot_capture_host`), calls `CaptureBridge.setup(engine, this)` before launch, then `FlutterActivity.withCachedEngine(...)`.
- Engine torn down in `onDestroy()` only when `isFinishing` (configuration-change safe).

## 4. Design Constraints Honored

- No changes to `ScreenCaptureService`, `MediaProjection`, `DebugCaptureExporter`, `CaptureProviderRegistry`, `WebViewCaptureProvider`, debug bubble, `capture_test.html`, compileSdk/targetSdk.
- Bridge never falls back to MediaProjection; capture source is the project-owned internal provider only.
